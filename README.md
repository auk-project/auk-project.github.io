# Auk Demo Page

Publication-grade demo page for **Auk**, a unified foundational model for speech generation and editing.
The site mirrors the visual language of [HunyuanVideo-Avatar](https://hunyuanvideo-avatar.github.io/) — Google Sans / Noto Sans typography, brand-blue accents sampled from the Tencent Hunyuan mark (`#0055E9` / `#00BCFF` / `#A8DFF5`), `is-max-desktop` container — while presenting the full Auk capability surface: 5 task families, 15 tasks, ~80 interactive audio players.

## Stack

- **Vite** + vanilla **TypeScript** (no UI framework)
- Custom `<canvas>`-based audio player (Web Audio API for waveform, native `<audio>` fallback)
- All demo content driven by typed data sources in `src/data/`

## Environment setup

Requires **Node.js ≥ 18** (tested on 20/22) and **npm ≥ 9**.

```bash
# 1. Install Node.js (if you don't have it)
#    macOS (Homebrew):  brew install node
#    or download from https://nodejs.org (LTS recommended)

# 2. Clone and install
git clone <your-repo-url>
cd <repo-dir>
npm install

# 3. Start the dev server
npm run dev
# → http://localhost:5173

# 4. Production build
npm run build
# → static output in dist/

# 5. Preview the production build locally
npm run preview
# → http://localhost:4173
```

### Troubleshooting

| Problem | Fix |
| --- | --- |
| `npm install` slow / network error | Use a mirror: `npm install --registry=https://registry.npmmirror.com` |
| Port 5173 in use | Vite auto-picks the next free port; check the terminal output |
| Audio doesn't play in dev | The page loads `public/assets/audio-norm/`; run `python3 scripts/normalize_audio.py` if that folder is missing |

## Asset layout

- `public/assets/audio/` — the **masters**: every task's input (source) audio, generated outputs, and slider stops (rate ×6, loudness ×7, pitch ×7). Named `<sample-id>-input.wav` / `<sample-id>-output.wav` / `rate-*`, `loudness-*`, `pitch-*`. Edited by hand; never overwritten by tooling.
- `public/assets/audio-norm/` — the **loudness-normalized mirror the page actually loads**, generated by `scripts/normalize_audio.py`. Same filenames and folder structure as the masters.
- `public/assets/figures/` — capability map, architecture diagram, pre-training taxonomy (`.png` + editable `.pdf`).
- `public/assets/brand/` — Hunyuan wordmark / mark, SJTU wordmark, SII seal.

## Audio loudness normalization

The demo set was recorded and generated at wildly different levels — the raw
spread was about 28 dB, so some clips were inaudible next to others. The page
therefore loads a pre-normalized mirror rather than normalizing in the browser.

```bash
python3 scripts/normalize_audio.py     # reads assets/audio/ → writes assets/audio-norm/
```

Every file referenced by `src/data/capabilities.ts` is measured with EBU R128
and moved to **−20 LUFS** by a single linear gain, clamped to keep the true peak
under −1.5 dBTP. A one-gain-per-file approach leaves each clip's internal
dynamics untouched; only its overall level changes.

**The Energy Edit clips are deliberately exempt** and copied byte-for-byte:
that demo exists to show loudness differences between its slider stops, so
normalizing them would erase the thing being demonstrated. The exemption is the
`VERBATIM_PREFIXES` tuple in the script.

Re-run the script after adding or replacing any master.

## Data sources

- `src/data/capabilities.ts` — five capability families, every operation, demo instructions, and audio asset mapping. **This is the file to edit when adding/updating demos.**
- `src/scripts/audio-player.ts` — the custom player: A/B track switching, waveform rendering, slider-driven stop selection.

### Instruction display modes

Each group sets `instructionMode` to say how its `Instruction:` line behaves:

| Mode | Behavior | Used by |
| --- | --- | --- |
| `always` | one static instruction for the card | TTS, Vocal Edit, Timbre Edit, Whisper Edit, Separate Speech |
| `track` | follows whichever output the card's switch selects | Content Editing, Emotion Edit, Nonverbal Edit |
| `none` | no instruction line at all | Enhance Speech, Extract Vocals, Improve Quality, Deaccent, and the three acoustic sliders |

## Card layout

Every card with a source clip stacks two labelled rows — **Input** above
**Output** — so an edit is heard and seen against the original without switching
away from it. Only Instruct TTS is a single player, since it generates from text
and has no input to compare against.

Whatever chooses between several outputs lives on the **Output** row: an A/B
switch (Content Editing's Add / Delete / Replace, Separate Speech's
Output1 / Output2) or a slider (emotion, rate, loudness, pitch). The Input row
never changes, and the instruction always describes the selected output — which
is why it no longer needs to hide itself.

Because the source now has its own row, a control that offers a "source" stop
never opens on it: the sliders start one stop past it and the emotion slider
starts on the stop furthest from the source clip's own emotion. Otherwise both
rows would play the same audio and the edit would look like a no-op. Landing on
such a stop by dragging is fine and is labelled as replaying the input.

A group with `inlineTranscript: true` folds the spoken text into the instruction
instead of showing it as a separate quoted block, since for text-to-speech the
text *is* the request; `transcriptConnector` sets the joining phrase.

## How to add or replace a demo audio

1. Drop the WAV under `public/assets/audio/` (e.g. `enhance-3-output.wav`).
2. Run `python3 scripts/normalize_audio.py` to refresh the normalized mirror.
3. In `src/data/capabilities.ts`, point the sample's `audio` field at the
   **`audio-norm`** path:
   ```ts
   { id: "enhance-3", lang: "en", label: "Enhance Speech · English",
     instruction: "Remove the background noise and make the voice clearer",
     audio: { src: "assets/audio-norm/enhance-3-input.wav", out: "assets/audio-norm/enhance-3-output.wav" } }
   ```
4. `npm run build` — cards with `src` + `out` automatically get the Input/Output A/B switch; cards with only `src` show the source on both sides as a placeholder.

> The `input_manifest.md` at the repo root documents every task's demo instruction and the seed-audio 1.0 prompt used to generate its input audio.

## Deployment

### Option A — GitHub Pages (recommended)

The build already uses `base: "./"`, so the site works under any subpath.

1. Push this repo to GitHub.
2. Repo → **Settings → Pages** → Source: **GitHub Actions**.
3. Add a workflow `.github/workflows/deploy.yml`:
   ```yaml
   name: Deploy to GitHub Pages
   on:
     push:
       branches: [main]
     workflow_dispatch:
   permissions:
     contents: read
     pages: write
     id-token: write
   concurrency:
     group: pages
     cancel-in-progress: true
   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with:
             node-version: 20
         - run: npm ci
         - run: npm run build
         - uses: actions/upload-pages-artifact@v3
           with:
             path: dist
         - uses: actions/deploy-pages@v4
   ```
4. Push, then enable Pages → the site appears at `https://<user>.github.io/<repo>/`.

### Option B — Any static host (Vercel / Netlify / Nginx)

`dist/` is fully static and self-contained.

```bash
npm run build
# upload / serve dist/ as the document root
# e.g. Netlify:  build command `npm run build`, publish dir `dist`
```

### Option C — Local static server

```bash
npm run build
npx serve dist
# or: python3 -m http.server 8080 --directory dist
```

## Notes

- The root-level `*.wav` files (Chinese-named source masters) are **not** committed; the demo page only uses the renamed assets under `public/assets/audio-norm/`, generated from `public/assets/audio/`.
- `node_modules/` and `dist/` are gitignored — always run `npm install` after a fresh clone.
